Étapes restantes

01tourRedémarrer

Retire la clé USB quand l'installateur le demande, puis appuie sur Entrée.

Tu arriveras soit sur Ubuntu, soit sur un menu noir (GRUB) listant Ubuntu et Windows.

Si Windows n'apparaît pas dans le menu

Il n'est pas perdu : il est intact sur le disque 0. Démarre-le par le menu de démarrage de ta carte mère (touche F8, F11 ou F12 au démarrage).

Pour l'ajouter au menu GRUB, depuis Ubuntu :

sudo os-prober
sudo update-grub

Si os-prober ne renvoie rien, ajoute la ligne GRUB_DISABLE_OS_PROBER=false dans /etc/default/grub, puis relance sudo update-grub.

02tourInstaller le serveur SSH

Ubuntu Desktop ne l'installe pas par défaut. Terminal : Ctrl+Alt+T

sudo apt update && sudo apt install -y openssh-server

Rien ne s'affiche pendant la saisie du mot de passe sous Linux — pas même des étoiles. C'est normal : tape et valide.

03tourRelever l'adresse IP

ip -brief addr

Note l'adresse qui commence par 192.168. — c'est celle du laptop vers la tour. Reporte-la dans le cadre en haut de ce document.

Pense à réserver cette adresse dans ta box (bail DHCP statique), sinon elle peut changer au prochain redémarrage.

04tourEmpêcher la mise en veille

Une machine qui s'endort n'est pas un serveur : la session SSH tomberait.

sudo systemctl mask sleep.target suspend.target \
                    hibernate.target hybrid-sleep.target

Dans Paramètres → Alimentation, mets aussi « Extinction d'écran » sur Jamais.

05laptopPremière connexion

Depuis PowerShell sur le laptop, avec l'IP relevée à l'étape 03 :

ssh flp@192.168.x.x

À la première connexion, une empreinte s'affiche avec la question Are you sure you want to continue connecting? → réponds yes.

06laptopSe connecter sans mot de passe

Génère une clé, une seule fois :

ssh-keygen -t ed25519 -C "laptop-thinkpad"

Puis dépose la clé publique sur la tour :

type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh flp@192.168.x.x `
  "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

Reconnecte-toi : le mot de passe ne doit plus être demandé.

07tourFermer l'accès par mot de passe

sudo tee /etc/ssh/sshd_config.d/99-durcissement.conf > /dev/null <<'EOF'
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
PubkeyAuthentication yes
MaxAuthTries 3
EOF

sudo sshd -t && sudo systemctl reload ssh

La seule manœuvre où l'on peut se verrouiller dehors

Ne ferme pas ta session SSH après l'étape 07. Ouvre une deuxième fenêtre et vérifie que la connexion fonctionne toujours.

Si elle est cassée, la session restée ouverte est le seul moyen de réparer sans rebrancher un écran sur la tour. sshd -t attrape les fautes de frappe, pas les erreurs de logique.

08tourPare-feu

sudo ufw allow OpenSSH
sudo ufw enable

L'ordre compte : autoriser SSH avant d'activer le pare-feu, sinon la règle te coupe de ta propre machine.

09tourAccès depuis l'extérieur — Tailscale

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Installe le client Windows sur le laptop, même compte. La tour reçoit une adresse 100.x.y.z stable, joignable de partout.

N'ouvre jamais le port 22 sur ta box. Un SSH exposé à l'internet est trouvé par des robots en quelques minutes. Avec Tailscale, il n'y a rien à trouver.

10tourOutils de développement

sudo apt install -y git tmux curl build-essential
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

Déconnecte-toi et reconnecte-toi pour que l'appartenance au groupe docker prenne effet.

11laptopAlias SSH et VS Code

Dans C:\Users\41411\.ssh\config :

Host tour
    HostName 192.168.x.x
    User flp
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
    LocalForward 3000 localhost:3000

ssh tour suffit désormais. Le LocalForward fait apparaître un serveur de développement de la tour sur localhost:3000 du laptop.

Dans VS Code : extension Remote – SSH, puis F1 → Connect to Host → tour.

Depuis Windows, Gestion des disques → supprimer les partitions du disque 1 → le reformater en NTFS. Tu récupères ton D: de 894 Go comme avant. Rien d'autre n'aura été modifié.
